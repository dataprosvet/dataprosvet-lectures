# Конспект: процессы и потоки

Краткая выжимка лекции 2.

## Процесс

Процесс — абстракция выполняющейся программы: экземпляр со своими PC, регистрами и переменными. CPU быстро переключается между процессами — **псевдопараллелизм**. Программа — рецепт; процесс — повар, который его готовит. Два запуска одной программы — два процесса.

Создание в UNIX: `fork` (клон) → обычно `execve` (новая программа). Между ними потомок может перенаправить stdin/stdout/stderr. Завершение: нормальный выход, ошибка, фатальный сбой, убийство другим процессом. Иерархия: process group; сигнал с клавиатуры — всей группе.

## Состояния

Три базовых: **Running / Ready / Blocked**.

- Running → Blocked: ждать событие (`pause` или автоблокировка).
- Running → Ready: планировщик отдал CPU другому.
- Ready → Running: снова очередь.
- Blocked → Ready: событие произошло.

UNIX детальнее (9 состояний): user/kernel running, ready in memory, asleep in memory, ready swapped, sleep swapped, preempted, created, zombie. Swapper — process 0. Preempted ≈ ready in memory, но вытеснение из kernel mode только перед возвратом в user mode.

## Реализация

**PCB / process table** — по записи на процесс: PC, SP, память, файлы, планировщик.

При прерывании: аппаратура сохраняет PC/PSW → vector → ассемблер сохраняет регистры и стек → C ISR → планировщик → возврат в новый процесс.

Загрузка CPU: процесс долю \(p\) времени ждёт I/O; при \(n\) процессах **utilization = \(1 - p^n\)**.

## Потоки

Поток — выполнение внутри общего адресного пространства. Быстрее процессов, перекрывают I/O и вычисления, на нескольких CPU дают настоящий параллелизм.

Примеры: текстовый процессор (ввод / формат / автосохранение); веб-сервер (dispatcher + workers + общий кэш). Три модели сервера: threads (параллелизм + блокирующие вызовы), single-thread (нет параллелизма), FSM (параллелизм + неблокирующие вызовы).

Общее у процесса: адресное пространство, глобалы, файлы, дети, alarms, сигналы, учёт. Личное у потока: PC, регистры, стек, состояние. У каждого потока свой стек.

Ловушки при переходе к multithreading: глобалы (`errno` перезаписывается), не-reentrant библиотеки, сигналы, стек. Лечение глобалов: запретить или private/threadwide globals. «Просто добавить потоки» без переработки не выходит.

## Purpose

Определяет текущую структуру приватного репозитория сдачи работ по API-технологиям: краткий каталог и одна общая ветка первого семинара и ДЗ без профилей.

## ADDED Requirements

### Requirement: Student repository is renamed for the 2026 course
Существующий `TheTonyPub/api-technologies-code` SHALL быть переименован в `TheTonyPub/api-technologies-2026` с сохранением GitHub repository ID, владельца, истории, приватности и прав доступа. Новая копия репозитория MUST NOT создаваться вместо переименования. `origin` локальной копии и актуальные ссылки в README, новых материалах и конфигурации курса SHALL использовать новый адрес. Локальная папка `/Users/ripper/projects/api-technologies-code` SHALL сохранять свой путь; преподавательский репозиторий не переименовывается.

#### Scenario: Renamed repository is verified
- **WHEN** завершено переименование и проверены GitHub metadata, локальный remote и актуальные ссылки
- **THEN** новый адрес открывает тот же repository ID с прежними владельцем, приватностью и правами, `origin` указывает на `TheTonyPub/api-technologies-2026`, а новые инструкции используют новый URL напрямую

#### Scenario: Target name belongs to another repository
- **WHEN** при подготовке обнаружен другой репозиторий `TheTonyPub/api-technologies-2026`
- **THEN** он не заменяется и не удаляется; переименование остаётся невыполненным до разрешения конфликта имени

### Requirement: Student repository retains main and one assignment branch
`TheTonyPub/api-technologies-2026` SHALL оставаться приватным и иметь ровно две текущие ветки: `main` и `seminar/01-api-scenarios`; default branch SHALL оставаться `main`. Остальные восемь веток исследованного среза SHALL быть удалены. Текущая локальная копия SHALL соответствовать удалённым веткам и их head SHA. Переписывание истории Git и изменение преподавательского репозитория MUST NOT входить в эту миграцию.

#### Scenario: Final branch inventory is checked
- **WHEN** после миграции перечислены локальные и GitHub-ветки репозитория сдачи
- **THEN** обе стороны содержат только две согласованные ветки с совпадающими head SHA, и GitHub сообщает default branch `main` и private visibility

### Requirement: README describes only seminar 1 and homework 1
README в `main` SHALL кратко описывать первый семинар, первое ДЗ и переход к `seminar/01-api-scenarios`. README учебной ветки SHALL различать работу на занятии и дома, описывать единый командный результат и способ сдачи через существующий Git/PR-процесс. Обе инструкции SHALL использовать единый язык без PRB/SII/COMMON-маркировки и не содержать ссылок на удалённые ветки, требований к ненужному окружению или полных условий локальных задач.

#### Scenario: Student opens the repository
- **WHEN** студент начинает с `main`
- **THEN** он находит только актуальные семинар 1 и ДЗ 1, переходит в общую учебную ветку и понимает, что сдаётся один назначенный командный кейс

### Requirement: Assignment branch has no profile split or obsolete exercises
Текущая учебная ветка SHALL не содержать `profiles/`, прежних профильных starter-файлов, контрактов, тестовых данных и проверок, относящихся к заменённому заданию. Семинар 1 и ДЗ 1 SHALL выполняться в одной рабочей линии; отдельная `homework/*` ветка и обязательная реализация сервисов для первого ДЗ MUST NOT вводиться.

#### Scenario: Clean assignment checkout is reviewed
- **WHEN** ветка первого семинара клонируется отдельно и проверяется по README
- **THEN** инструкция не требует файлов другой ветки или выбора профиля, а оставшиеся файлы соответствуют архитектурному этапу нового задания

### Requirement: Removal is recoverable and does not consume unrelated work
Перед удалением веток SHALL существовать проверенная локальная резервная копия их актуальных refs и объектов вне выдаваемого студентам содержимого. Миграция SHALL сохранять незакоммиченные правки и проверять актуальные ветки, PR и защиты непосредственно перед удалением. Неизвестные новые ветки или чужие изменения MUST NOT удаляться по устаревшему списку.

#### Scenario: Remote state changes after planning
- **WHEN** перед удалением обнаружены новые ветки, новые коммиты или открытые PR, которых не было при исследовании
- **THEN** план удаления пересматривается по актуальному состоянию, затронутые новые работы сохраняются, а завершение миграции не заявляется до разрешения расхождения

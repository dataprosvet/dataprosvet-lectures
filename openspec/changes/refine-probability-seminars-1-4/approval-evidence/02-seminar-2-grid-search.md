## Текущий фрагмент

> В машинном обучении комбинаторика возникает при настройке гиперпараметров — это внешние настройки модели, которые мы выбираем до обучения (например, количество слоёв нейросети, число нейронов в каждом слое, скорость обучения и т.п.). Представьте, что у нас есть 7 слоёв, и для каждого нужно выбрать один из 3 типов активации — это $3^7 = 2187$ комбинаций. Если добавить выбор числа нейронов (4 варианта для каждого слоя), то число архитектур вырастает до $(3 \cdot 4)^7 = 12^7 \approx 35$ миллионов. Полный перебор (Grid Search) здесь невозможен.

## Полное восстановление текущего решения

1. Для каждого из семи слоёв независимо выбирается один из трёх типов активации:

   $$
   3^7=2187.
   $$

2. После добавления четырёх вариантов числа нейронов один слой имеет

   $$
   3\cdot4=12
   $$

   пар настроек «активация × число нейронов».

3. Для семи слоёв по правилу произведения получается

   $$
   12^7=35\,831\,808\approx35{,}8\text{ млн}
   $$

   архитектур. Текущее округление «примерно 35 миллионов» грубое, но по порядку величины верное.

4. Grid Search по определению рассматривает все точки заданной сетки. Однако из количества точек без времени одного обучения нельзя вывести абсолютную невозможность. Если одна конфигурация требует времени $t$, последовательное время равно

   $$
   T=35\,831\,808\,t.
   $$

   | Время одной конфигурации | Полное время без распараллеливания |
   |---:|---:|
   | 1 мс | около 9,95 часа |
   | 1 с | 414,72 суток |
   | 1 мин | около 68,13 года |

   При $k$-fold cross-validation потребуется как минимум $k\cdot12^7$ обучений; например, при пяти фолдах — $179\,159\,040$ обучений, не считая итогового refit.

## Проверка по источникам

- В. Е. Гмурман, печатные с. 22–23: правило произведения обосновывает умножение числа независимых вариантов и степень $12^7$; учебник не устанавливает вычислительный порог невозможности.
- Т. И. Савелова, «Метод Монте-Карло», с. 113: полное время $N$ вычислений при времени одного вычисления $t$ равно $T=Nt$.
- Официальная документация scikit-learn определяет `GridSearchCV` как исчерпывающую проверку всех комбинаций сетки, указывает независимую оценку комбинаций по фолдам и возможность параллельного выполнения: https://scikit-learn.org/stable/modules/grid_search.html
- Bergstra и Bengio сравнивают Grid Search и Random Search при одинаковом вычислительном бюджете; их результат обосновывает практическую неэффективность полного поиска в ряде задач, но не универсальную логическую невозможность при фиксированном числе точек: https://www.jmlr.org/papers/v13/bergstra12a.html

## Предлагаемый полный фрагмент

В машинном обучении комбинаторика возникает при настройке гиперпараметров — это внешние настройки модели, которые мы выбираем до обучения (например, количество слоёв нейросети, число нейронов в каждом слое, скорость обучения и т.п.). Представьте, что у нас есть 7 слоёв, и для каждого нужно выбрать один из 3 типов активации — это $3^7 = 2187$ комбинаций. Если добавить выбор числа нейронов (4 варианта для каждого слоя), то число архитектур вырастает до $(3 \cdot 4)^7 = 12^7 = 35\,831\,808$. Полный перебор (Grid Search) потребует обучить и оценить модель для каждой архитектуры, поэтому обычно становится практически неприемлемо дорогим; фактическая выполнимость зависит от времени одного обучения, доступного распараллеливания и вычислительного бюджета.

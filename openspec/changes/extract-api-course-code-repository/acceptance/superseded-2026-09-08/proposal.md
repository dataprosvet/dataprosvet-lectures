## Why

Исполняемый контур первых четырёх лекций и первых пяти практических работ сейчас находится в `attachments/api-learning-path/`, хотя `attachments/` предназначен для скачиваемых приложений к материалам курса. Студенческий код и закрытый преподавательский контур необходимо отделить от Markdown-репозитория курса и друг от друга, разместить в двух приватных GitHub-репозиториях и закрепить этот способ авторинга для всех следующих материалов.

## What Changes

- Создать локальный Git-репозиторий `/Users/ripper/projects/api-technologies-code`, приватный GitHub-репозиторий `TheTonyPub/api-technologies-code` и связать их remote `origin`.
- Добавить в student-facing репозитории каталогизирующую ветку `main`, четыре автономные ветки `lecture/*` для демонстраций лекций 1–4 и пять автономных веток `seminar/*` для практических работ № 1–5; семинары 5–6 используют одну ветку практической работы № 5.
- Перенести в соответствующие ветки student-facing код, контракты, синтетические данные, starters, public checks и README с командами установки, запуска и проверки.
- Сохранить `PRB` и `SII` как явно выбираемые маршруты внутри одной ветки задания, не умножая ветки по профилям.
- Создать локальный Git-репозиторий `/Users/ripper/projects/api-technologies-code-teacher` и отдельный приватный GitHub-репозиторий `TheTonyPub/api-technologies-code-teacher` для instructor solutions, instructor checks, grading fixtures и внутренней validation-инфраструктуры.
- Зеркалировать в teacher-репозитории имена учебных веток student-репозитория, сохраняя однозначное соответствие выдаваемого starter и закрытого эталона.
- Запушить `main` и все созданные учебные ветки в соответствующие приватные GitHub-репозитории и проверить visibility `PRIVATE` и remote branch inventory.
- Обновить Markdown первых четырёх лекций, семинаров 1–6 и ДЗ 1–5: заменить пути `attachments/api-learning-path/...` реальными ссылками на `https://github.com/TheTonyPub/api-technologies-code/tree/<branch>` и описать единый рабочий контур «семинар → продолжение в ДЗ».
- После проверки эквивалентности удалить перенесённый исполняемый student-facing контур из `attachments/`, оставив `attachments/` для настоящих приложений к материалам.
- Дополнить `openspec/config.yaml` обязательными правилами создания новых лекций, семинаров и ДЗ, соответствующих code branches, README, student/teacher separation, профильной трассировки, ссылок и проверок.
- Зафиксировать модель будущей сдачи: студент получает ветку семинара из upstream, продолжает практику и ДЗ в одном приватном репозитории и одном PR; фактическое создание студенческих репозиториев и GitHub-автоматизация в этот change не входят.
- **BREAKING**: существующие команды и ссылки с префиксом `attachments/api-learning-path/` перестанут быть каноническим способом запуска кода курса.

## Capabilities

### New Capabilities

- `course-code-distribution`: определяет два приватных GitHub-репозитория кода, автономные учебные ветки, безопасное разделение студенческих и преподавательских артефактов, ссылки из Markdown, постоянные authoring-правила и проверяемую миграцию существующего контура.

### Modified Capabilities

- Нет. Учебные результаты и содержание существующих лекций, практик и ДЗ не меняются; меняется способ хранения и выдачи исполняемых артефактов.

## Impact

- Репозиторий курса: `attachments/api-learning-path/`, `lectures-teacher/001..004`, `seminars/001..006`, `homeworks/001..005`, `openspec/config.yaml`, OpenSpec acceptance evidence и команды валидации.
- Student-facing контур: `/Users/ripper/projects/api-technologies-code` и приватный `TheTonyPub/api-technologies-code`, его ветки, README, зависимости, тесты, контракты и синтетические данные.
- Teacher-only контур: `/Users/ripper/projects/api-technologies-code-teacher` и приватный `TheTonyPub/api-technologies-code-teacher`, зеркальные ветки, решения, закрытые проверки и grading fixtures.
- Совместимость: все ссылки и команды, зависящие от старого расположения, должны быть заменены и проверены до удаления исходных файлов.
- GitHub: создание двух private repositories и push веток выполняются через текущую внешнюю `gh`-авторизацию аккаунта `TheTonyPub`; `course.yaml`, GitHub Organization, приватные студенческие репозитории, PR automation и deployment не изменяются.
- Scope: `COMMON` с отдельными вариантами `PRB` и `SII` внутри соответствующих учебных веток.
- Non-goals: материалы лекций 5–9, практические работы 6–12, создание студенческих репозиториев, настройка reviewers/дедлайнов и GitHub Actions, публичная публикация репозиториев и решение ранее открытого вопроса о публичных профилях курса.

# Заметки преподавателя: процессы и потоки

Спикер-нотов в исходном PPTX нет (только номера слайдов). Ниже — акценты по содержанию слайдов, без добавленных фактов.

## Цели занятия

Студент должен уметь:

- отличить программу от процесса и объяснить псевдопараллелизм
- описать `fork`/`execve` и четыре причины завершения
- назвать три состояния (Running/Ready/Blocked) и четыре перехода
- прочитать диаграмму UNIX (created → ready → kernel/user running → asleep/preempted/swapped → zombie)
- объяснить PCB и скелет обработки прерывания
- посчитать идею CPU utilization = \(1 - p^n\)
- отличить поток от процесса и заполнить таблицу «общее / личное»
- объяснить dispatcher/worker и конфликт глобала (`errno`)

## На что давить

- Слайды 6–8: один PC vs четыре логических PC — якорь «процесс = виртуальный CPU».
- `fork` без `execve` — клон; перенаправление fd — между ними.
- Трёхсостоячная схема (слайд 15) до UNIX-девятки (слайд 24). Слайды 25, 27, 29, 31 — те же диаграммы с подсветкой пути; не тратить время на повтор картинки, пройти путь verbally: created → ready in memory → kernel running → user running → preempted; syscall + I/O → asleep; swapper; exit → zombie.
- Preempted vs Ready in memory: почти одно и то же, но вытеснение из kernel mode только перед возвратом в user.
- Формула \(1 - p^n\): \(p\) — доля ожидания I/O у одного процесса, \(n\) — степень мультипрограммирования.
- Три процесса vs один процесс с тремя потоками (слайд 49) — визуальный якорь multithreading.
- Веб-сервер: общий кэш в user space; dispatcher не делает диск, workers делают.
- `errno`: гонка на глобале; private globals — не «магия», а отдельное хранилище на поток.

## Типичные ошибки

- «Несколько процессов одновременно на одном CPU» — в каждый момент один; иллюзия за счёт переключений.
- «Программа = процесс» — два запуска одной программы — два процесса.
- «Blocked = Ready» — blocked ждёт событие; ready может идти, но CPU отдан другому.
- «Zombie занимает CPU» — процесс уже не существует, осталась запись для родителя.
- «Потоки не разделяют память» — наоборот: общее адресное пространство; личные PC, регистры, стек.
- «Hyper-threading из прошлой лекции = три потока текстового процессора» — здесь про программные threads.

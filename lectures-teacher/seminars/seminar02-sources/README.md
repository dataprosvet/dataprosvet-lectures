# Семинар 2 — простые HTTP-моки, версия 2

Четыре приложения используют общий образ `api-seminar-002-app:2`. Здесь только основные HTTP-сценарии: фиксированный прогноз, имитация приёма JSON и запрос одного сервиса к другому. Внешний вид и поведение web-интерфейса сохранены; адреса подставляются из настроек.

## Запуск

Из этой папки, при работающем Docker Desktop:

```sh
docker compose up -d --build --remove-orphans --wait
```

Откройте http://127.0.0.1:8003. Swagger UI: http://127.0.0.1:8000/docs, http://127.0.0.1:8001/docs и http://127.0.0.1:8002/docs. Его JS/CSS лежат локально, интернет после сборки не нужен. Версии Python и зависимостей закреплены. Остановка: `docker compose down`.

При переходе с версии 1 `--remove-orphans` убирает контейнеры БД, почты и seed старого демо. Старые тома автоматически не удаляются. Версия 2 их не использует.

## Живая схема сервисов

Откройте **http://127.0.0.1:8004**. Отдельный observer читает реальные события mitmweb каждые 0,5 секунды. Схема подсвечивает связи, журнал показывает метод, путь, статус и фактическую задержку. Ошибки красные. Движение точки длится примерно секунду для наглядности и не изображает реальную скорость пакетов.

Работают как кнопки на странице, так и curl/Swagger/старый web-интерфейс. Например, оставьте схему открытой и выполните:

```sh
curl -i 'http://127.0.0.1:8002/offices/42/forecast?days=1'
```

Появятся внешний запрос к OfficeManager и его обращение к Read API. Клиент определяется по peer IP: IP контейнера OfficeManager распознаётся через Docker DNS, остальные инициаторы объединены в «Внешний клиент». Отдельные браузеры и curl не различаются. Схема показывает наблюдаемые связи; общего trace-id для причинного сопоставления параллельных запросов нет.

Кнопки выполняют настоящие запросы через traffic, а не запускают заранее нарисованную анимацию. «Очистить экран» скрывает старые записи только в этой вкладке; mitmweb продолжает хранить свои flows. Нажатие на запись повторяет подсветку и раскрывает детали. Заголовки и тела доступны в mitmweb по ссылке снизу. Отсутствие связи с mitmweb отображается отдельно от пустого списка запросов.

Источник ограничен последними 150 подходящими flows, журнал показывает последние 100. /docs, статика и проверки готовности скрыты. Прямые обращения к API в обход traffic не наблюдаются. Файлы observer.py и web/observer.html — инструмент преподавателя, не новый материал о FastAPI для студентов. Согласованные C4 и прежняя web-страница сохранены.

## Наблюдение HTTP в браузере — mitmweb

Откройте **http://127.0.0.1:8081**. Учебный пароль по умолчанию: **seminar02**. Он задаётся в Compose через MITMWEB_PASSWORD; это локальный демонстрационный доступ, все опубликованные порты привязаны к loopback.

Сервис traffic использует дополнительный образ около 277 MB и запускает официальный mitmproxy 12.2.3 в режиме reverse proxy. Бизнес-код приложений не меняется. Прежние публичные адреса API сохранены, но теперь эти порты публикует наблюдатель:

| Обращение | Маршрут |
|---|---|
| Web / curl / Swagger → localhost:8000 | traffic:8000 → read-api:8000 |
| curl / Swagger → localhost:8001 | traffic:8001 → bank-offices:8000 |
| curl / Swagger → localhost:8002 | traffic:8002 → office-manager:8000 |
| OfficeManager → READ_API_URL | traffic:8000 → read-api:8000 |

На запрос к OfficeManager видны две записи: внешний запрос к OfficeManager и его вложенное обращение к Read API. Время этих записей перекрывается, их нельзя складывать как независимые этапы. В списке адрес назначения показан после перенаправления (read-api, bank-offices или office-manager), а не обязательно localhost.

Показ на паре:

1. Откройте mitmweb рядом с web-страницей. В поле фильтра введите `~u /offices/ | ~u /observations`, чтобы убрать загрузки Swagger и статики.
2. Получите прогноз в web-интерфейсе. Запись появится без перезагрузки mitmweb.
3. Выполните запрос к OfficeManager на порту 8002 — покажите два HTTP-обмена.
4. Выполните POST /observations из примеров ниже. Выберите запись: Request — метод, URL, заголовки и JSON; Response — статус и тело; вкладки Connection и Timing — соединения и времена.
5. Замените visitors на −1 и сравните 201 с 422. Не включайте перехват с остановкой запроса (intercept), если нужна обычная непрерывная демонстрация.

Трафик HTTP незашифрованный, сертификаты устанавливать не нужно. Видны только запросы, прошедшие через traffic. Список хранится в памяти mitmweb; после пересоздания контейнера он очищается. Наблюдатель добавляет задержку, поэтому это не проверка SLA. Он является инструментом занятия, а не новым бизнес-сервисом на согласованной C4.

Для повторного запуска: `docker compose up -d --wait`. Проверка готовности наблюдателя обращается к /openapi.json трёх API; эти служебные записи скрываются указанным фильтром. Анимированная схема доступна отдельно на порту 8004; mitmweb остаётся подробным просмотрщиком HTTP.

### Wireshark на macOS

На loopback-интерфейсе lo0 можно смотреть обращения компьютера к опубликованным портам; display filter: `tcp.port == 8000 || tcp.port == 8001 || tcp.port == 8002`. Для чтения HTTP при необходимости используйте Decode As → HTTP и Follow → TCP Stream. Интерфейс mitmweb на 8081 лучше исключить, чтобы не смешивать учебный HTTP и обновление наблюдателя.

Межконтейнерные пакеты Docker Desktop идут внутри Linux VM и на lo0 macOS не обязаны появляться. Для них нужен захват внутри Docker VM/сетевого пространства контейнера с последующим открытием pcap в Wireshark. Установка Wireshark на хост сама по себе этот доступ не добавляет. Захват пакетов и дополнительные привилегированные контейнеры в комплект не включены.

Официальные справочники: [reverse proxy](https://docs.mitmproxy.org/stable/concepts/modes/#reverse-proxy), [параметры mitmweb](https://docs.mitmproxy.org/stable/concepts/options/).

## Как сервисы находят друг друга

Compose подключает контейнеры к общей bridge-сети `services`. Внутри неё OfficeManager обращается к `http://traffic:8000`: Docker разрешает имя `traffic` в адрес наблюдателя mitmweb. Он пересылает запрос в `http://read-api:8000`. Используется внутренний порт приложения, не порт хоста.

Адрес задаётся в Compose:

```yaml
environment:
  READ_API_URL: http://traffic:8000
```

Python читает обязательную настройку `os.environ["READ_API_URL"]` при создании HTTP-клиента. Запасного localhost нет: отсутствие настройки обнаруживается при запуске. При запуске Python вне Docker задайте эту переменную самостоятельно, например `READ_API_URL=http://127.0.0.1:8000`.

Проверить из контейнера OfficeManager:

```sh
docker compose exec office-manager python -c 'import os, httpx; url = os.environ["READ_API_URL"]; print(url); print(httpx.get(url + "/offices/42/forecast", params={"days": 1}, timeout=2).status_code)'
```

Ожидается `http://traffic:8000` и `200`. Эта сеть предназначена для связи контейнеров; `internal: true` не включён, исходящий доступ не блокируется. Loopback-порты сохранены для браузера, Swagger UI и curl. Браузер не знает Docker-имён: web-страница продолжает обращаться к опубликованному 127.0.0.1:8000, поэтому её CORS-настройка сохраняется.

Все адреса задаются в compose.yaml:

| Переменная | Кто использует | Назначение |
|---|---|---|
| READ_API_URL | OfficeManager | Внутреннее обращение к traffic:8000 → read-api:8000 |
| WEB_ORIGIN | Read API | Разрешённый origin браузерной страницы |
| READ_API_PUBLIC_URL | Web | Запрос прогноза и ссылка на Swagger |
| BANK_OFFICES_PUBLIC_URL | Web | Ссылка на Swagger BankOffices |
| OFFICE_MANAGER_PUBLIC_URL | Web | Ссылка на Swagger OfficeManager |

Web-сервер подставляет три публичных адреса в HTML-шаблон. В Python и HTML нет зашитых localhost-адресов. BankOffices только отвечает на запросы, поэтому адреса чужих API ему не нужны. При изменении публичных портов согласованно измените ports, публичные URL и WEB_ORIGIN в Compose. Порты 8000 внутри контейнеров могут оставаться одинаковыми.

Для запуска служебного экспорта контрактов вне Docker также задайте READ_API_URL и WEB_ORIGIN. В сервисе tools эти значения уже указаны.

## Что читать на занятии

1. `read_api.py`: декоратор задаёт путь; параметры функции получают значения из URL; `if` выбирает успех или ошибку; словарь становится JSON.
2. `bank_offices.py`: `observation: dict` получает JSON-тело, две простые проверки и ответ 201.
3. `office_manager.py`: один `httpx.Client` с base_url и пулом соединений; обработчик вызывает client.get и передаёт ответ.

Нет своих классов исключений, моделей Pydantic, response_model, Annotated, Depends, middleware обработки ошибок, БД или фоновых задач. CORS в Read API нужен только для сохранённой страницы на другом порту. `docs.py`, Dockerfile и инструменты проверки — служебная подготовка преподавателя; разбирать их на первом занятии не нужно.

## Основные сценарии

Готовый прогноз: 200, 24 точки для одного дня, 168 для недели:

```sh
curl -i 'http://127.0.0.1:8000/offices/42/forecast?days=1'
```

Неизвестный офис: 404 `office_not_found`. Известный офис без результата: 404 `forecast_not_ready`. Неподдерживаемый горизонт: 422 `invalid_request`.

```sh
curl -i 'http://127.0.0.1:8000/offices/999/forecast'
curl -i 'http://127.0.0.1:8000/offices/43/forecast'
curl -i 'http://127.0.0.1:8000/offices/42/forecast?days=30'
```

Имитация успешного приёма: 201. Замените 45 на −1: будет 422.

```sh
curl -i -X POST 'http://127.0.0.1:8001/observations' \
  -H 'Content-Type: application/json' \
  -d '{"office_id":42,"visitors":45}'
```

Данные не сохраняются. Повтор возвращает тот же 201 и фиктивный id. Поле hour можно передать, но оно не проверяется. Нет Location, защиты от повторов или полной проверки схемы. POST не меняет готовый прогноз.

Вызов через OfficeManager:

```sh
curl -i 'http://127.0.0.1:8002/offices/42/forecast?days=1'
```

Резерв — недоступность зависимости:

```sh
docker compose stop read-api
curl -i --max-time 30 'http://127.0.0.1:8002/offices/42/forecast?days=1'
docker compose up -d --no-deps read-api
```

Ожидается 503. Это показывает отказ HTTP-связи, не измеряет SLA. DNS Docker может добавлять время к тайм-ауту клиента.

## Пул соединений OfficeManager

В lifespan при запуске приложения создаётся один httpx.Client. Он хранится в app.state.read_api и используется всеми синхронными обработчиками этого процесса. Повторные запросы могут переиспользовать TCP-соединение. Контекст with закрывает клиент и пул при остановке приложения. Тайм-аут — 2 секунды, лимиты пула стандартные HTTPX. При нескольких процессах у каждого свой пул.

Для этого примера используется обычный def и синхронный Client. Если обработчик станет async def, нужен AsyncClient и await; блокирующий get туда переносить не следует.

## Что здесь является моками

`forecast.json` — фиксированные учебные значения, включая даты и `stale: false`. Свежесть и модель не вычисляются. Готовая C4 описывает целевую архитектуру; этот комплект демонстрирует только несколько её HTTP-взаимодействий. PostgreSQL, EmailServer и workers не запускаются. Диаграммы не являются схемой развёртывания моков.

Ошибки, написанные в обработчиках, имеют форму `error: {code, message}`. Для неверного типа URL-параметра (например, days=abc), повреждённого JSON и неизвестного маршрута FastAPI использует собственный ответ `detail`. Намеренно не добавляем обработчики для унификации. Для показа используйте перечисленные выше запросы.

Автоматический OpenAPI в `/docs` помогает попробовать пути и параметры, но обычный dict не описывает обязательные поля, все ответы и бизнес-ограничения. JSON-файлы `contracts/*.json` — экспорт именно этого упрощённого описания, не образец полноценного контракта ДЗ. JSON тела POST в Swagger введите вручную: `{"office_id":42,"visitors":45}`.

### Покрытие согласованного контекста C4

Web UI и Read API входят в ClientFlowPredictor. OfficeManager запрашивает у него готовые данные. В моках отсутствуют интеграции ClientFlowPredictor → BankOffices и ClientFlowPredictor → EmailServer; прямой POST к BankOffices — отдельное упражнение HTTP. Преподаватель согласовал это частичное покрытие. Живая схема объединяет внешних клиентов и не является точной C4 уровня 1.

## Лекция 2: авторский OpenAPI 3.2.1

[contracts/lecture02-openapi.yaml](contracts/lecture02-openapi.yaml) описывает две выбранные операции мока со схемами, примерами и ошибками. Откройте **http://127.0.0.1:8000/lecture-02**. Страница получает именно этот YAML с `/lecture-02/openapi.yaml`; обычная `/docs` продолжает показывать автоматически созданный `/openapi.json` с неполными бизнес-схемами. Оба вида документов имеют OAS 3.2.1, но разное назначение.

В UI: раскройте GET → Parameters/Responses → Try it out → office_id=42, days=1 → Execute. Сравните Response body/Code с образцом Example Value, затем попробуйте days=7. Enum допускает только 1/7; серверный отказ для days=2 покажите отдельно:

```sh
curl -i 'http://127.0.0.1:8000/offices/42/forecast?days=2'
```

Ожидается 422 и `error.code=invalid_request`. days=abc вызывает другую, стандартную ошибку FastAPI с `detail`. Никакого единого Problem Details middleware здесь нет.

Для POST прочитайте requestBody, ссылку `#/components/schemas/Observation` и ответ 201. У операции другой server — порт 8001. BankOffices не настроен на межсерверный CORS, поэтому Execute POST со страницы Read API не используется; реальный POST выполняется через curl из раздела «Основные сценарии». Мок не сохраняет наблюдения и не подтверждает защиту от повторов.

Проверенные инструменты: Swagger UI 5.32.15 (локальные assets, источник и целостность в static/swagger-provenance.json), openapi-spec-validator 0.9.0, jsonschema 4.26.0. Runtime FastAPI/Pydantic сохраняет прежние версии. Валидатор рассчитан на учебный однофайловый документ с локальными ссылками, JSON-совместимыми встроенными примерами и схемами Draft 2020-12; сложные новые streaming-примеры OAS 3.2 не входят в его учебное покрытие. Проверка формата не доказывает полноту или соответствие реальному серверу.

```sh
.venv/bin/python validate_contract.py contracts/lecture02-openapi.yaml contracts/read-api.json contracts/bank-offices.json contracts/office-manager.json openapi-template.yaml
WEB_ORIGIN=http://127.0.0.1:8003 READ_API_URL=http://127.0.0.1:8000 .venv/bin/python -m pytest -q -p no:cacheprovider
```

### Запуск показа без Docker

Python 3.12 и установленные по requirements.txt зависимости; из каталога комплекта:

```sh
.venv/bin/python run_lecture.py
```

Команда поднимает три API на loopback-портах 8000–8002; Ctrl+C останавливает только запущенные ею процессы. Порты должны быть свободны. Это отдельный режим для показа контракта: web/observer/mitmweb не запускаются, OfficeManager обращается к Read API напрямую. Полный семинар с наблюдением трафика запускается прежним Compose. Проверка работающих API из второго терминала: `python3 smoke.py`.

Запасной показ без сервера: открыть YAML, [сохранённый обмен](lecture-02-reserve/exchanges.md) и тела ответов рядом с ним. Снимок показывает конкретный проверенный обмен синтетического мока, не текущую работу сервера и не подтверждение доступности.
